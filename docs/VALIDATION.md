# 验证范围

本记录区分离线测试、目录浏览、实际文件下载和退出清理。只发布验证结论，不附带设备导出文件、连接参数、会话记录或个人路径。

## 离线测试

在 Windows 上运行基础测试；未配置外部来源时，集成套件以 1 项跳过标记呈现：

```powershell
node --test test/*.test.cjs
```

2026-10-27 的公开仓库验证结果：**89 项测试，88 项通过，1 项跳过，0 项失败**。跳过项是未提供外部来源包的集成套件。

指定兼容的 Windows `ns2jb-ftp` 来源目录后，同时运行外部来源集成测试：

```powershell
$env:OUNCECAKE_NS2JB_SOURCE = 'C:\path\to\ns2jb-ftp'
node --test test/*.test.cjs
```

覆盖 RPC 等待与退出、命名管道路径、会话选择、只检查模式、完整/仅本体模式、缺失与空内容处理、更新挂载资源清理，以及 FTP 启停和 `q` 退出等行为。卡带模式新增参数互斥、分区枚举、失败清理、报告与宿主路径配置检查。来源副本不随仓库发布；GitHub Actions 使用 Windows、Node.js 22 / 24 检查无需该来源包的基础套件。离线测试不证明任意主机版本或游戏的硬件兼容性。

## 本分支解决的问题

- **Windows 连接适配：**生成独立 RPC 环境，跳过来源引擎的 FTP 和自动导出，避免同时运行两个 FTP 服务。
- **更新挂载超时：**移除更新 RomFS 路径对固定 FS 全局地址的依赖，使用现有注册接口建立本次临时上下文，并在完成后注销同一 owner。FS 对象修改保留预期值和读回检查。
- **空 FTP：**报告缺失分区和挂载文件数；没有文件时直接结束并提示原因。
- **退出残留：**增加 `q` / `quit` 退出，等待 FTP 与挂载资源清理完成后才输出 `Stopped`；输入流结束不会自行放弃服务所有权。
- **卡带逻辑分区访问：**新增独立卡带模式，保留原游戏内容模式；修复上述 Switch 2 环境中旧 DeviceOperator 查询导致的会话关闭，改用当前卡带内容路径。

这些改动已通过上述范围的测试，仍需在其他来源版本、主机版本和游戏上分别验证。
